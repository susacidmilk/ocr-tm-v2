# 设计说明 · OCR 翻译记忆库 v2

> 本文是该应用的**实现设计说明**：架构、数据模型、模块接口、提示词与调度策略、边界与风险。
> 适合想了解内部实现或参与二次开发的读者。

---

## 0. 需求一句话与设计决策

让用户既能**实时逐句翻译**（边玩边看），也能**挂机批量录制**一段剧情 → 整段编号提交 DeepSeek（高质量、按游戏隔离）→ 逐句对齐写入**本地翻译记忆库**；以后同一段剧情再现，实时命中秒显，不重复调 API。历史记录栏体验全面重做。

**关键设计决策**

| 项 | 结论 |
|---|---|
| 形态 | 独立 Electron 桌面应用，模块化分层 |
| 代码结构 | 模块化/接口解耦，状态清晰，可扩展 |
| 数据 | 全新独立目录，不依赖任何外部历史 |
| 模式 | 实时逐句翻译 **与** 批量录制→整段翻译 **并存** |
| 对齐单位 | 按 OCR 逐条原文编号对齐 |
| 批量大小 | 可调参数（默认 50，档位建议 10–200） |
| TM 作用域 | **按游戏隔离** |
| 命中 | 精确清洗匹配为主；未命中给“疑似命中”提示，不自动采用 |
| 历史同句 | **只留一行**：记最早出现时间 / 最新出现时间 / 命中计数，不新增行 |
| 保留能力 | 实时 OCR 逐句翻译、本地 LM Studio 源、导出、悬浮层完整细节 |
| 明确不默认保留 | 独立“游戏词表”模块（若后续要则按扩展加回） |

## 1. 目录结构与模块解耦

新应用按能力拆模块，模块之间只通过**明确接口**通信（renderer ↔ main 经 preload 的 IPC 接口；main 内部各模块用事件/依赖注入），为以后越做越复杂留解耦余地。

```
game-ocr-v2/
├─ package.json
├─ src/
│  ├─ main/
│  │  ├─ index.js            # 入口：装配各模块、创建窗口、事件接线
│  │  ├─ data/
│  │  │  ├─ store.js         # 通用原子写(JSON) + 目录
│  │  │  ├─ tm.js            # 翻译记忆库(每游戏): load/upsert/get/search/export/clear + norm索引
│  │  │  ├─ records.js       # 会话历史(每游戏/每会话): 同句合一行语义
│  │  │  └─ settings.js      # 设置持久化(含每源配置/模式等)
│  │  ├─ ocr/
│  │  │  ├─ capture.js       # 拉起 ocr-worker.ps1 常驻进程、按帧读取
│  │  │  ├─ stabilizer.js    # typewriter 稳定帧判定(复用现有思路)
│  │  │  ├─ route.js         # 认到新句后按【模式】分派: 实时 或 录制
│  │  │  └─ garble.js        # 乱码检测与自动停止
│  │  ├─ translate/
│  │  │  ├─ sources/         # 可插拔翻译源(同一 Provider 接口)
│  │  │  │  ├─ deepseek.js   # 单句流式 + 整段非流式(编号数组)   [默认]
│  │  │  │  └─ lmstudio.js   # 本地 LM Studio(OpenAI兼容)         [可选同接口]
│  │  │  ├─ queue.js         # 翻译队列(实时槽位与批量槽位分开)
│  │  │  └─ batch.js         # 整段分块→编号请求→对齐校验→二分/单句兜底→写TM
│  │  ├─ match/
│  │  │  ├─ norm.js          # computeNorm 清洗键
│  │  │  ├─ exact.js         # TM精确命中 + hits++
│  │  │  └─ fuzzy.js         # 疑似命中(编辑距离/相似度候选, 供人工确认)
│  │  └─ windows/            # main/overlay/picker 窗口管理 + overlay避让
│  ├─ preload/               # contextBridge 暴露命名空间(见 §7)
│  ├─ renderer/
│  │  ├─ index.html/css/js   # 主界面(含模式切换、历史、状态栏)
│  │  ├─ batch.html/css/js   # 批量录制+TM管理 视图
│  │  ├─ picker.html/css/js  # 框选识别区
│  │  └─ overlay.html/css/js # 置顶悬浮层
│  └─ shared/
│     ├─ events.js           # 事件类型常量(renderer/main 共用)
│     └─ constants.js        # 默认设置/模式枚举/阈值默认
└─ ocr-worker.ps1            # 常驻 OCR 进程(从旧工程复制并按需整理)
```

**解耦原则**
1. 数据层不依赖窗口/渲染。
2. 翻译源实现同一 `Provider` 接口：`translateLine(raw,{onPartial,cfg})` 与 `translateBatch(lines,cfg)` → main 里按当前源选取，与模式无关。
3. 状态全部在 main 持有并经事件广播；renderer 只做展示与发指令，避免状态两处漂移。
4. 各模块用事件类型常量（`shared/events.js`）解耦字符串。

## 2. 数据层设计

### 2.1 数据目录（全新）
`<userData>/ocr-tm-v2/`
- `settings.json`
- `records/<safeGame>.json`（会话历史，**同句只留一行**）
- `tms/<safeGame>.json`（翻译记忆库 TM）
- 每个 `<safeGame>` 由游戏名做文件安全化。

### 2.2 TM 单条结构
```jsonc
{
  "id": "uuid",
  "game": "My Game",
  "raw": "Hello there.",          // 规范后原文(展示)
  "norm": "hello there",          // 清洗键(computeNorm)
  "translated": "你好呀。",
  "model": "deepseek-chat",
  "src": "deepseek",              // 恒 deepseek(批量)/或实际源
  "addedAt": 0, "updatedAt": 0,
  "hits": 0,
  "status": "translated",         // translated | error
  "error": null,
  "meta": { "chunk": 3, "idx": 17 }
}
```

### 2.3 会话历史单条（同句合一行语义）
```jsonc
{
  "id": "uuid",
  "game": "My Game",
  "sessionId": "...",
  "norm": "hello there",
  "rawFirst": "Hello there.",      // 最早出现原文
  "rawLast": "Hello there.",       // 最新出现原文(OCR噪声修复后可能不同)
  "translated": "你好呀。",        // 来自 TM/实时翻译
  "model": "...", "src": "deepseek",
  "firstSeenAt": 0,               // 最早出现时间
  "lastSeenAt": 0,                // 最新出现时间
  "count": 5,                     // 命中次数(同句出现次数)
  "status": "translated",         // pending|translating|translated|error
  "error": null,
  "flags": { "fromTm": true }     // 是否由 TM 秒显
}
```
> **合并规则**：同 `norm` 且同 `sessionId` → 不新增行，只更新 `rawLast/lastSeenAt/count++`。跨会话则新起一行(会话不同行)。
> 这是对现有 bug“同一句反复加进历史”的修复——由 `records.js` 在 upsert 时统一处理。

## 3. 清洗键 computeNorm（命中基准，入库与查询同一入口）
`shared` 或 `match/norm.js` 提供，按源语言清洗：
- 折叠空白/换行→单空格；转小写。
- 去除句中装饰符号（首尾与独立符号 `-_=|"'‘’“”:;` 等），保留词内撇号（`don't`）。
- 按 Token 清洗：切 token → 去首尾标点 → 保留词内合法字符。
- 入库、精确命中、疑似命中、历史合并 **都用同一函数**。

## 4. 模式与录制（实时 vs 批量，解耦的 route）

认到新句的**分派器 route.js**（复用现有稳定帧/去重/乱码检测，但目标可切换）：

```
handleStableText(raw)
  ├─ computeNorm(raw)
  ├─ 乱码? -> 停/跳过
  └─ mode === 'live'
        └─ 历史 upsert(同句合并)
             ├─ TM精确命中? -> 秒显TM译文(hits++, count++) [不调API]
             ├─ 疑似命中? -> 提示, 人工确认后采用或忽略
             └─ 未命中 -> 实时翻译 -> 写TM + 历史
     mode === 'record' (批量录制)
        └─ 录制累加器:
             ├─ 已在pending/TM本游戏? -> 跳过(提示已收录)
             └─ 否则 append 到当前录制清单(pending[])
```

**录制状态机**
- `idle` → `recording`（OCR 在跑且向 pending 追加）→ `paused/recorded`（可翻译）→ `translating`（整段翻译中）→ `done`（写入 TM）→ 清空回 idle 重录。

**界面需让状态“一目了然”**：顶部状态徽章显示 当前模式、OCR 是否在跑、录制中句数、翻译进行中块数/失败、TM 该游戏总句数。任何操作前后状态都可见、可打断。

## 5. 整段提交与对齐（质量核心）

复用并强化现有 `callDeepSeekOnce` + `extractJsonArray` 思路，但**长度硬校验 + 二分/单句兜底**：

- 分块：`batchSize` 可调(默认50)。块内顺序=剧情顺序。
- 请求格式：编号 1..N 逐句，要求返回**恰好 N 个元素的 JSON 数组**，禁止合并/拆分/漏译/改序；人名/专有名词保留；有术语约束则附 system。低温度(0.3)。
- 解析：`extractJsonArray` 取数组 → **长度校验**。
- 失败策略：长度不符/请求错 → **二分缩小**该失败块重试，递归至单句；单句仍失败则标 error 待手动重试。不整块重翻省 API。
- 看门狗：沿用 `withDeadline`，单块超时不堵后续块。
- 每条成功 → `tm.upsert(norm)`。
- 批量任务走**独立队列**，不与实时翻译抢槽位。

---

## 6. 实时命中与疑似命中
- 精确：`norm` 完全相等 → 秒显 TM 译文，TM.hits++、history.count++，不调 API、不建重复历史行。
- 疑似：精确未命中且本游戏 TM 存在高相似候选(编辑距离/比例阈值可调,默认较严)→ 给“疑似候选+差异度”，**由用户确认采用/忽略**，不自动采用。
- 相似检索 MVP 对本游戏子集线性扫描；量大命中频繁再做索引。

## 8. 界面与状态（重做 §11 痛点）

### 8.1 主界面
- 顶部：**模式切换(实时/批量)**、全局状态徽章(模式·OCR·录制·翻译·TM计数)。
- 历史记录区重做（针对你点名的体验问题）：
  - **同句只留一行**（见 §2.3），重复出现只增 count/最新时间，不再反复加。
  - **紧凑排版**：每条目一行内排列 —— `时间(最早) · 出现x次` | 原句 | 译句 | `[重新翻译]` `[删除本条]`，**按钮与文本同排不换行**；条目间**用换行分隔、不用卡片/框隔开**。
  - **“重新翻译”不回推悬浮层**：点击后译文只更新在该历史行内；悬浮层展示由“当前命中的实时句”单独决定，两者解耦。改为：命中式秒显由 route 控制，手动“重新翻译”只刷新该条历史/对应 TM，不 focusOverlay。
- 右侧/页签可切到 **批量录制视图**（或独立窗口）。

### 8.2 批量录制视图
- 开始/停止录制、已录句数、原文清单预览（只读，可删个别怪句、可编辑单句、可清空重录）。
- “整段翻译”按钮 + 进度：总块/完成/失败/待重试。
- 翻译完成后提示“已写入本游戏翻译记忆库 N 句”。

### 8.3 TM 管理视图
- 按游戏浏览/搜索(原文或译文)/导出(JSON 或 TXT 双语)/删除单条/清空本游戏。
- 显示该游戏 TM 总句数与总命中。

### 8.4 悬浮层
- 保留完整细节：字号(译文/原文)、更新滞后 overlayRevealDelayMs、可锁点击穿透/解锁拖动、位置记忆、避开识别区、来源标。

## 10. 边界与风险（明示）
1. 对齐可靠性仍是最大风险 → 长度硬校验+二分/单句兜底；用真实对白试跑调 batchSize。
2. **模型“回显原文”现象（已实测确认，已加防护）**：真实 DeepSeek 整段批量翻译时，即使 `temperature:0`，模型仍会**偶发把原文原样返回而不翻译**（实测 3/5 次回显）。对一个“翻译记忆库”而言这很危险——会把未翻译的原文当“译文”缓存。已在批量路径加入**回显防护**：源/目标语言不同时，若某条返回与原文一致，判定为回显 → 对该条用单句（更清晰提示词）单独重试一次；整批全回显则二分重试。活体测试从“3/5 回显”降到“0/5”，且真译结果稳定。→ 阶段 C 的界面应在“失败/重试”中显式展示这类回显重试，便于用户识别。
3. 疑似命中靠人工确认，交互偏重；默认关自动采用。
4. 数据按游戏隔离，同一句不同游戏各翻一次（用户已接受）。
5. 全新数据不迁移 → 旧历史/词表在新应用不可见；如有需要后续做一次性导入按钮（不默认）。
